Tinyclass tests a narrow question: can a lesson stay genuinely small without becoming shallow?

## The format

A class contains one explanation, one worked example, and one exercise. There are no accounts, streaks, dashboards, or points. Progress is stored locally in the browser.

| Part | Purpose |
| --- | --- |
| Explanation | Establish one useful mental model |
| Example | Show the model doing real work |
| Exercise | Give the reader a way to test it |

## Design decisions

The first prototype hid too much behind progressive disclosure. It looked tidy, but readers could not see the shape of the lesson. The current version keeps the whole outline visible and uses `<details>` only for optional hints.

<Details summary="Why the project is paused">
The lesson format needs testing with real material before the application needs more features. The next step is to write three complete lessons, not to expand the interface.
</Details>

## What I learned

A small educational product still needs a strong point of view about sequence. Removing features does not remove the need to decide what a learner should encounter first.
